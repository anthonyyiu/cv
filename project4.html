Project Report

Motivation

I recently became interested in learning about horse racing after seeing viral posts of the horses on social media and was captivated by their eccentric personalities and mannerisms. My motivations were to make a personal project, as well as learn more about the sport through making this.

Problem

The main problem I intend to solve with this website is data organization and accessibility. With horse race records, the data is very dense and extensive, so through data visualizations, the information can be communicated efficiently and effectively, albeit broadly.

Target Audience

New or casual horse racing enthusiasts are the intended audience – people who are not experts but want to familiarize themselves with the sport, and even potentially bet at their local racecourses. This website offers general, broad, all-time data, local and racecourse-specific data, and horse lineage record data, which may interest any fan.

Dataset

https://www.kaggle.com/datasets/hwaitt/horse-racing/data

This was the main dataset used, though it is not perfect, is missing entries, and has a skewed focus with Great Britain.

Limitations and Challenges

  • At first, because the dataset was large (~90mb), I had to use Microsoft cloud file connection to import it in ObservableHQ, which made the loading speed very slow.
  • Midway through the project, I realized the dataset did not give units for currency or speed. I ended up cross-referencing a few races, to find that the prizes matched in Pound Sterling.
  • One parameter I didn't understand was what "TR – Top Speed" meant. The numbers didn't make sense for mph or km/h. Looking it up online suggested it meant "speed rating" – a measurement of speed accounting for several track conditions. That sounded correct at first, but online records showed that a speed rating of 140 was already the peak, while the numbers from the dataset far exceeded that. I was further confused and decided to remove that visualization.
  • After setting up the GitHub website, I noticed that it took a long time to load the website and was nearly impossible to load on mobile. I hypothesize that this was due to having too many Observable visualization embeds. I later tidied the code to not load various previous versions of the same Observable notebook.
  • Additionally, the Leaflet map markers that I wanted to sync with the dataset have this error where, even though I checked the data exists, selecting certain racecourse markers display a blank visualization.

Improvements (Future Work)

  • If I were to make more changes, I think finding a more consistent and accurate dataset would be the first step. Then I could better organize my data and have more parameters to work with.
  • One feature I think is unfeasible currently would be to reenact past races and allow the user to place bets. At minimum, this would require extensive race results data and it would be impossible to acquire the positions throughout the race if I wanted to properly animate/recreate the race itself. Although, just simply displaying the results of the bet, without any animation at all, could suffice.
  • I would also want to have a specific horse data section, similar to the "specific racecourse" section, where such data like lineage, farm statistics, rivals, and career performance visualizations would be displayed. To take this a step further, with "rivals," two horses could be compared if they have raced before, to show a race history and how both have placed in comparison to one another.
